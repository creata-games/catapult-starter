# Катапульта — правила помощника

Учебный проект Creata Academy: ученик строит свою 2D-физическую головоломку на Unity. Старт содержит пустую сцену Main и настройки инструментов. Здесь нет готовой игры, уровней или утверждённого игрового плана.

## Начало работы

Прочитай README.md, kit/README.md и, если есть, PLAN.md и историю git. Если плана ещё нет, помоги ученику составить его по теме 1. Не создавай заранее механики, тестовые башни, уровни или решения заданий. Сначала представь план изменений в рамках задачи ученика. Если задача и план уже согласованы, выполняй их без повторного запроса согласия.

Формат задачи: цель · контекст и файлы · рамки · готовый результат · проверка. Решения об объёме, внешнем виде и параметрах игры принимает ученик. Не выдавай догадки о наличии ассетов за факт: kit/ содержит только инструкцию и настройку связи.

## Стек и структура

- Unity 6000.3.26f1, C#, 2D URP с Renderer2D. Версии закреплены в Packages/manifest.json и packages-lock.json.
- Ввод — Input System; новые действия создавай в Assets/Settings/Input/ по плану. Legacy Input.GetKey не используй.
- Пиксель-арт: Sprite, Point, Compression None, без mipmaps, PPU 16; камера Pixel Perfect 480×270. Первый импорт изображений в Assets/Art/ настраивает Assets/Editor/PixelArtDefaults.cs; уже сохранённые настройки он не меняет. Изменения масштаба согласуй с задачей.
- Assets/Scripts/ — будущий игровой код; Assets/Data/ — будущие данные; Assets/Prefabs/ и Assets/Scenes/ — префабы и сцены.
- Assets/Art/Sprites/, Assets/Art/Tiles/, Assets/Audio/ — ассеты ученика. Исходники генерации держи вне Assets/, например в _raw/.
- Assets/Tests/EditMode/ и Assets/Tests/PlayMode/ — будущие тесты с собственными asmdef. Пустые папки не означают наличие пройденных тестов.
- ЖУРНАЛ.md и ИИ-ЖУРНАЛ.md дописывай только по просьбе ученика; личные решения и распределение работы за него не выдумывай.

## Работа с кодом и редактором

- Один скрипт — одна задача; параметры, которые должны меняться без кода, выноси в данные по согласованному плану. Не копируй готовое игровое решение из другого проекта.
- Ссылки задавай через сериализуемые поля; не ищи объекты и компоненты каждый Update. Для 2D используй 2D-физику; физические действия выполняй в соответствующем физическом цикле.
- Через MCP изменяй проект только при остановленном Play Mode. Открытые в Unity сцены и префабы не переписывай на диске: используй редактор.
- tests-run запускай последовательно. Не уничтожай служебную сцену InitTestScene… раннера. Тесты должны изолировать сохранения игрока.
- При зависшем MCP, ошибке Failed to invoke RunCallTool или tests-run без завершения дольше пары минут сообщи ученику и прекрати зависимые действия. Не вызывай внутренние методы плагина для обхода блокировки.

## Локальный MCP

AI Game Developer 1.1.0, режим Custom, адрес http://localhost:9048. .mcp.json настраивает клиент Claude Code; пользовательскую настройку Unity создаёт kit/prepare-local-mcp.py до первого открытия. Cloud не используй.

Список инструментов меняет только человек: rql-query, rql-mutate, rql-schema, script-execute, tests-run, unity-tool-list, screenshot-isolated, screenshot-game-view, screenshot-scene-view. Если нужный инструмент недоступен, сообщи об этом; не обходи отсутствие инструмента кадра через script-execute.

## Ограничения

- Работай внутри этого проекта. Не применяй sudo и не меняй системные настройки.
- Не редактируй Library/, Temp/, сгенерированные meta и ProjectSettings/ без задачи на соответствующие настройки. Meta создаёт Unity.
- Не добавляй и не обновляй пакеты, плагины, ассеты из внешних источников или дополнительные CLI/skills без указания ученика.
- Не удаляй сцены, префабы и тесты; не отключай и не ослабляй проверки ради зелёного результата.
- Секреты хранятся вне проекта или в окружении. Не запрашивай их значения в чате, не печатай их и полные ответы API; не сохраняй ключи и токены в файлах проекта, логах и сборке.
- Не публикуй, не пушь и не делай коммиты без явного указания ученика. Перед шагом напомни сохранить рабочую версию; самовольный коммит не является критерием готовности.

## Проверка результата

Сверь изменения с задачей. Проверь Console, выполни подходящие EditMode/PlayMode проверки, если они созданы. Не называй нулевое количество тестов успешной проверкой механик. Импорт стартового проекта не проверяет ещё не написанную игру.

Изменения графики проверь кадром Game View и предложи ученику посмотреть его и сыграть. Кадр и зелёные тесты проверяют разные вещи. Batchmode запускай при закрытом редакторе с этим проектом, указывай настоящий код возврата и путь лога. Не подменяй неудачный запуск строкой rc=0.

В конце отчёта напиши: что сделано, что добавлено сверх задачи, что не сделано, какие проверки реально прошли и что осталось непроверенным.
