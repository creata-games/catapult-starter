# Твой стартовый проект «Катапульта»

Здесь ты начинаешь тему 1 практикума Creata Academy. Распакованный проект станет твоим собственным: план, бросок, башню, данные и проверки ты создашь по заданиям темы.

## 1. Что внутри и что установить

| Путь | Что ты получаешь |
| --- | --- |
| Assets/Scenes/Main.unity | Пустая сцена с камерой Pixel Perfect: 480×270, 16 пикселей на юнит |
| Assets/Settings/ | URP с 2D Renderer |
| Assets/Editor/PixelArtDefaults.cs | Только настройка первого импорта изображений в Assets/Art/: Sprite, Point, None, PPU 16, без mipmaps |
| Assets/Scripts/, Data/, Prefabs/, Art/, Audio/, Tests/ | Папки для твоей работы; игровых скриптов и тестов пока нет |
| Packages/ | Закреплённые версии Unity-пакетов и AI Game Developer 1.1.0 через OpenUPM |
| ProjectSettings/ | Настройки 2D, Input System и пиксельной графики |
| .mcp.json | Клиент Claude Code подключается по HTTP к localhost:9048 |
| CLAUDE.md, AGENTS.md | Правила помощника |
| ЖУРНАЛ.md, ИИ-ЖУРНАЛ.md | Пустые формы для твоих решений и учёта работы |
| kit/local-mcp-config.json | Шаблон локального режима Custom без секретов |
| kit/prepare-local-mcp.py | Создаёт пользовательские настройки MCP перед открытием Unity |

В этом kit/ нет картинок, звука, шрифта и placeholder-ассетов. Не проси помощника копировать отсутствующие kit/sprites/ и kit/audio/ из образцов лабораторной. В теме 1 ты создашь временную геометрию сам или с помощником; к теме 2 подготовь свой набор и реестр источников. Никакие ключи генерации для старта не нужны.

Поставь Unity Hub и редактор **6000.3.26f1** с WebGL Build Support, Git, Python 3 и Claude Code. Войди в Unity Hub и активируй подходящую лицензию. Для Claude Code используй свой доступ; не вставляй пароли и ключи в проект. Установка помощника описана в [официальной инструкции](https://code.claude.com/docs/en/setup).

Проверь в терминале `git --version` и `claude --version`. На macOS проверь `python3 --version`, на Windows — `py -3 --version`. Если команда не найдена, заверши установку и открой терминал заново. Unity CLI для этого старта не нужен.

## 2. Распакуй и подготовь локальный режим ДО Unity

Не открывай проект прямо внутри ZIP. Распакуй весь архив, сохраняя скрытые файлы, в обычную локальную папку с правом записи. Внутри catapult-starter должны лежать Assets, Packages, ProjectSettings и .mcp.json. На macOS скрытые файлы в Finder показывает Cmd+Shift+точка.

Unity для этой копии пока должен быть закрыт. Скрипт ниже создаёт только UserSettings/AI-Game-Developer-Config.json. Он переносит шаблон Custom с локальным адресом, включает девять инструментов и оставляет автозапуск соединения выключенным, пока ты не проверишь настройки. Существующий файл он не перезаписывает.

**macOS, Terminal** — пример для папки в домашнем каталоге:

```sh
cd "$HOME/catapult-starter"
python3 kit/prepare-local-mcp.py
```

**Windows, PowerShell** — пример для папки в профиле:

```powershell
Set-Location "$env:USERPROFILE\catapult-starter"
py -3 kit/prepare-local-mcp.py
```

В обеих командах подставь свой путь, если распаковал в другое место. Ожидаемое сообщение начинается с `Local MCP prepared` или `Local MCP settings already exist`.

Без Python можно сделать то же вручную при закрытой Unity: создай UserSettings в корне проекта, скопируй туда kit/local-mcp-config.json и переименуй копию в AI-Game-Developer-Config.json. При включённом скрытии расширений Windows проверь, что получилось именно `.json`, а не `.json.json`. Если файл уже существует, сначала сохрани его копию и изучи настройки.

**Повторяй этот шаг для каждой свежей распаковки.** UserSettings не входит в архив и игнорируется Git. Один .mcp.json не переключает режим Unity-плагина: без подготовки плагин использует свой облачный режим по умолчанию.

## 3. Открой проект через Unity Hub

1. На Windows открой Unity Hub из меню «Пуск», на macOS — из Applications/«Программы».
2. В Installs/«Установки» проверь версию 6000.3.26f1. В меню редактора → Add modules добавь WebGL Build Support, если его ещё нет.
3. В Projects/«Проекты» нажми Add → Add project from disk. Выбери **папку catapult-starter**, где лежат Assets, Packages и ProjectSettings. Создавать ещё один проект по шаблону не нужно.
4. Открой его именно в 6000.3.26f1. Не соглашайся на случайное обновление версии. Дождись импорта: Unity скачивает пакеты, а плагин — зависимости NuGet; нужен интернет к Unity Registry, OpenUPM и NuGet. Локальный сервер плагина загружается отдельно при его запуске, нужен доступ к серверу загрузки плагина.
5. Если открылся Safe Mode, сначала прочитай первую ошибку Console. Не выбирай обновление пакетов вслепую. Для ошибки лицензии проверь Unity Hub → Licenses; для ошибки загрузки — подключение к сети. Сохрани точный текст и обратись за помощью.
6. В Project открой Assets/Scenes/Main.unity. Открой окна Hierarchy, Inspector, Console и **Game**. В Hierarchy ожидается только Main Camera, а в Game — пустой одноцветный фон. У камеры должны быть Camera, Audio Listener, Universal Additional Camera Data и Pixel Perfect Camera с PPU 16 и 480×270. Ошибок Missing Script быть не должно.
7. Проверь Edit → Project Settings → Player → Other Settings → Active Input Handling: Input System Package (New). В Graphics/Quality используется UniversalRP с Renderer2D, сглаживание выключено. В Project Settings → Editor режим проекта — 2D.

Временные Library, Logs и UserSettings Unity создаст сама. Не переноси их между компьютерами. Windows-маршрут требует проверки на Windows: в исходном кейсе он не был проверен.

## 4. Запусти MCP локально

1. В Unity открой Window → AI Game Developer. До подключения проверь **Custom** и **http://localhost:9048**. При Cloud остановись и переключи на Custom. Не выбирай облачную авторизацию для этого маршрута.
2. Нажми Start для локального сервера; при первой загрузке дождись окончания. Затем подключи редактор кнопкой Connect, если он ещё не подключён. Ожидается статус работающего сервера и подключённого редактора. Отдельный ключ для этого локального соединения не нужен.
3. В списке инструментов проверь девять включённых: rql-query, rql-mutate, rql-schema, script-execute, tests-run, unity-tool-list, screenshot-isolated, **screenshot-game-view**, **screenshot-scene-view**. При необходимости включи последние два вручную. Список меняешь ты, а не помощник.
4. Оставь Play Mode выключенным и окно Game открытым. Держи открытым только один учебный проект на порту 9048. Если порт занят другим проектом, останови его сервер либо выбери свободный порт и одинаково измени адрес в Unity и в .mcp.json этого проекта.

Сервер работает на твоём компьютере. Облачный MCP ai-game.dev не нужен, однако Claude Code обрабатывает твои запросы своим сервисом; не передавай ему секреты.

## 5. Подключи Claude Code и проверь кадром

1. Открой Terminal или PowerShell в корне **этого** проекта тем же `cd`/`Set-Location`, что выше. Выполни `claude`.
2. При первом запуске войди в свой аккаунт, проверь путь доверенной папки и одобри проектный MCP-сервер **unity** из .mcp.json. Оставь обычные подтверждения действий помощника.
3. Выполни `/mcp`. Сервер unity должен иметь статус connected.
4. Напиши: «Прочитай CLAUDE.md. Сними кадр Game View через screenshot-game-view и опиши, что на нём. Ничего в проекте не меняй».
5. Убедись, что помощник вызвал инструмент кадра и показал изображение пустого фона. Одного ответа «подключено» недостаточно. Запиши в ЖУРНАЛ.md дату, Custom, адрес, результат `/mcp` и путь сохранённого кадра.

Если unity не найден, проверь текущую папку и скрытый .mcp.json. При disconnected проверь Start/Connect, адрес и запущенный редактор. При отсутствии инструмента кадра включи его в Unity и перезапусти Claude Code. При зависании не запускай много одинаковых запросов: останови работу, сохрани сообщение ошибки и перезапусти редактор вручную. Не обходи инструменты кадра скрытыми вызовами.

Если MCP недоступен, тема допускает работу вручную: открывай и проверяй сцену в редакторе, сохраняй кадры Game и записывай конкретный блокер. Это не считается пройденной проверкой MCP.

## 6. Сохрани своё начало и переходи к теме 1

Когда убедишься, что это твоя учебная папка, создай локальную историю. Команды одинаковы в обоих терминалах:

```sh
git init
git check-ignore -v Library/ UserSettings/ _tmp/ Builds/ .env
git status --short
git add -A
git commit -m "старт практикума"
```

Перед git add проверь список: секретов и служебных папок там быть не должно. Если Git просит имя и email, настрой свой профиль самостоятельно; значения в архиве не заданы. Создание истории выполняешь ты; в выданном архиве нет .git и готовых коммитов.

Прочитай правила, заполни начало журналов и попроси помощника составить свой PLAN.md по теме 1. В образцах лабораторной SampleScene, Menu, Game и карта Catapult.inputactions относятся к последующей работе: здесь стартовая сцена называется Main. Уточни план создания или переименования сцен; не считай эти файлы уже существующими. Готовый игровой план и метки шагов в архив не входят.

Для проверки будущих тестов используй Window → General → Test Runner, сначала EditMode, затем PlayMode. Пока игровых тестов нет, пустой список тестов ожидаем. Перед проверкой импорта через batchmode закрой эту копию редактора. Batchmode требует активной лицензии и не заменяет кадр и ручной плейтест.
